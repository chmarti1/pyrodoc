Properties of many ideal gases

As of version 2.2.5, the data collection includes 985 unique ideal gas models, including pure substances and mixtures. Through a convenient object interface, the following properties are available:

  • cp Isobaric specific heat
  • cv Isochoric specific heat
  • d Density
  • e Internal energy
  • gam Specific heat ratio
  • h Enthalpy
  • mw Molecular weight
  • R Ideal gas constant
  • s Entropy
  • v Specific volume

Multi-phase equation-of-state models

As of version 2.2.5, the data collection includes seven detailed multi-phase equation of state models.

  • N2 Diatomic nitrogen
  • O2 Diatomic oxygen
  • CH4 Methane
  • CO2 Carbon Dioxide
  • H2 Carbon Dioxide
  • C2H2F4 R134a
  • C3H2F4 R1234ze

These provide properties:

  • cp Isobaric specific heat
  • cv Isochoric specific heat
  • d Density
  • e Internal energy
  • gam Specific heat ratio
  • h Enthalpy
  • mw Molecular weight
  • R Ideal gas constant
  • s Entropy
  • v Specific volume
  • x Quality

Work in whatever units you prefer

Users can reconfigure the entire property management system to work in whatever unit system they prefer with one or two lines of Python. The system automatically transitions between mass- and molar-based matter calculations so you don't have to. 

>>> pm.config['unit_matter'] = 'kmol'
>>> pm.config['unit_temperature'] = 'C'

All your favorite (and probably some of your least favorite) units are included. If you see an important unit missing, please email me!

Pythonic array support

PYroMat provides thermodynamic properties for nearly 1,000 substances. Fast and intuitive access to the properties of each substance comes from calling up objects. Properties are calculated by object methods that support array-like objects as arguments.

If you want to calculate the properties of air, you load PYroMat, then, you ask for PYroMat's air model. Then, you ask it whatever you want to know. 

>>> import pyromat as pm
>>> air = pm.get('ig.air')
>>> air.gam(T=[300, 400, 500, 600])
array([1.39990859, 1.39519249, 1.38666408, 1.37575277])

Balance of performance and ease of use

PYroMat is written in pure Python, which does not have a reputation for speed. However, these codes are specifically designed to take full advantage of the back-end speedups that come from vectorization. It seems unlikely that Python will ever be as fast as a compiled code written for a similar task, but when code is written to take appropriate advantage of the powerful compiled back-end tools in Python's numerical packages, it is astonishing how well Python can perform.

All of the property models are coded in pure Python, but the implementation makes full use of Numpy's precompiled array support. For example, the multi-phase models require numerical iteration on formulae that can be expensive to evaluate, but even large data sets can be analyzed in convenient times. The test below was on a lightweight laptop with an Intel i3-1006G1 1.2GHz processor using a single core. 

>>> setupstr = """import pyromat as pm
... import numpy as np
... h2o = pm.get('mp.H2O')
... N = 100
... T=np.linspace(300,1000,N)
... p=np.linspace(0.1,10,N)"""
>>> teststr = """h2o.h(T=T,p=p)"""
>>> timeit.timeit(teststr, setupstr,number=100)/100

Clearly, PYroMat is not intented to be used for back-end property calculation in multi-million cell CFD simulations. In fact, few detailed property calculation codes are. On the other hand, it is a viable tool for cycle analysis and all sorts of other modeling where precise equation-of-state models are important.

PYroMat users can play their role in getting better performance as well. For example, if an application calls for more than one property at a state, rather than calculating them with individual property calls, it is far more efficient to use the state method implemented in version 2.2.0. This method returns a dictionary with just about all the properties a user could want, and it is only marginally slower than an individual property lookup.
